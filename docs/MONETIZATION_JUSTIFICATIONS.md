# Monetization “Not Power” Justifications (Registry)

This registry assigns stable IDs to “why this is not power” arguments for each SKU/category. Receipts reference these IDs via `not_power_justification_id`.

## Format

Each entry should include:

- `id` — stable id used in receipts
- `sku` — the purchasable identifier
- `category` — cosmetic/memory/convenience/world_support/service
- `policy_ref` — constitution reference (doc + article)
- `argument` — short proof sketch (why this is not power)
- `measurement` — how we validate it stays non-power (if applicable)
